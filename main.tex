\bluebigheading{PROPOSAL DESCRIPTION }

\vspace{7mm}

\blueheading{Motivation }

\vspace{2mm}

\answerbox[5.4cm]{Urban traffic congestion is a growing problem, especially at intersections controlled by fixed-time signals that allocate green light duration without regard to actual traffic conditions. This leads to unnecessary waiting time, increased fuel consumption, and pollution when vehicles idle at red lights for roads with little or no traffic, while congested roads remain stuck waiting their turn. As vehicle numbers rise faster than road infrastructure can expand, static signal timing becomes increasingly inefficient. An intelligent traffic optimization system that dynamically adjusts green light duration based on real-time vehicle count can significantly reduce congestion, cut average waiting time, lower fuel wastage, and minimize unnecessary stopping at near-empty roads. Solving this problem is important not only for daily commuter convenience but also for reducing carbon emissions and improving overall urban mobility and safety, particularly by allowing priority handling for emergency vehicles.}

\vspace{7mm}

\blueheading{State of the Art / Current solution }

\vspace{2mm}

\answerbox[4.2cm]{Most traffic signals currently in use operate on fixed-time cycles, where each road is given a pre-set green light duration regardless of actual traffic volume. Some modern systems use basic sensors or timers to make minor adjustments, but they generally lack real-time, data-driven decision-making. A few advanced smart-city deployments use camera-based AI vehicle detection integrated with adaptive signal control, but these solutions are costly and not widely implemented, especially in developing regions. As a result, most intersections still suffer from inefficient timing, leading to congestion at high-traffic roads and wasted green time at low-traffic roads.}

\vspace{7mm}

\blueheading{Project Goals and Milestones }

\vspace{2mm}

\answerbox[7.6cm]{\textbf{General Goals:} Detect and count the number of vehicles waiting at each road of an intersection; calculate real-time traffic density per road; dynamically optimize green signal duration based on that density; prioritize roads with the highest traffic volume or emergency vehicles; simulate the traffic light system and compare its performance against fixed-time signals.

\vspace{2mm}
\textbf{Milestones:}
\begin{enumerate}[leftmargin=5mm, itemsep=0.3mm, parsep=0pt, topsep=1mm]
    \item Design the vehicle detection and counting module.
    \item Implement traffic density calculation logic.
    \item Build the signal timing optimization algorithm using appropriate data structures (queues, priority queues, graphs).
    \item Develop the traffic light simulation module.
    \item Integrate all modules into a working end-to-end system.
    \item Evaluate results and compare performance against fixed-time signal systems.
\end{enumerate}}

\blueheading{Project Approach }

\vspace{2mm}

\answerbox[6.3cm]{The system will be developed in \textbf{C++} using an object-oriented design with classes (\textit{TrafficSignal}, \textit{Road}, \textit{Vehicle}) to simulate intersection traffic. Core functionality is built on structured algorithms and data structures:
\begin{itemize}[leftmargin=5mm, itemsep=0.4mm, parsep=0pt, topsep=1.5mm]
    \item \textbf{Queue:} Holds waiting vehicles sequentially per lane at each traffic light.
    \item \textbf{Priority Queue:} Decides next green signal by prioritizing highest density and emergency vehicles.
    \item \textbf{Graph Structure:} Models the road network topology and interconnected intersections.
    \item \textbf{Stack \& Linked List:} Logs historical signal state events (Stack) and maintains live vehicle records dynamically (Linked List).
    \item \textbf{Arrays \& Control Loops:} Tracks vehicle tallies across roads and executes real-time timing updates.
\end{itemize}}

\blueheading{Assumptions}

\vspace{2mm}

\answerbox[3.4cm]{It is assumed that vehicle counts can be obtained accurately (via simulated sensor input rather than live camera hardware), that all roads at an intersection have comparable lane capacity, that emergency vehicle detection is simulated through a flagged input rather than real sensor hardware, and that environmental factors such as weather and accidents are not modeled in this version.}
